## Core Technical Concepts

### 1. API (Application Programming Interface)
* **Definition:** An API is a software intermediary that enables different applications or systems to communicate and exchange data or functionality with each other.
*  **Example:** When a weather app shows the current temperature, it uses a weather API to request weather data from a server and display it to the user without collecting the data itself.

### 2. AI API (eg. Google AI Studio/ Gemini API)
* **Definition:** An AI API is an interface that allows developers to access and use AI capabilities, such as text generation, image creation, or speech recognition, within their own applications.
*  **Example:** A startup building a tournament website can use the AI API of OpenAI to automatically generate summaries. The website sends match details to the AI API, an the AI returns a professionally written summary that is displayed to the users.

### 3. API Key
* **Definition:** An API key is a unique secret code used to identify and authenticate an application when it accesses an API.
* **Example:** If a developer wants to use teh AI API of openai.com in their app, they must include an API key with each request. The API key tells the service which application is making the request and whether it has permission to use the API.

### 4. Request and Response
* **Request:** A request is the data or message sent by a user or application to an API asking for a specific service or information.
* **Response:** A response is the data or result returned by the API afte processing the request.
* **Example:** When a user enters "Write a leave application" in an AI-powered website:
  1. **Request:** The website sends the prompt "Write a leave application to the AI API".
  2. **Response:** The AI API returns a complete leave application generated by the  AI.

### 5. JSON (JavaScript Object Notation)
* **Definition:** JSON is a lightweight and structured data format used to store and exchange information between applications and APIs.

## The AI Integration Workflow (How it Works)

When a user clicks an AI button on Tournyx, the data travels through the technical stack in a simple loop using this exact path:

### The Arrow-Flow Chain:
Tournyx Frontend (UI Button) ➔ Tournyx Backend (Server + API Key) ➔ Gemini API (AI Model) ➔ Tournyx Backend (Server Response) ➔ Tournyx Frontend (Display Screen)

---

### Step-by-Step Breakdown:

* **Step 1: The Click (Frontend UI)** A tournament organizer clicks a button on the Tournyx website that says *"Generate Custom Rules"*.

* **Step 2: The Package (Backend Server)** The Tournyx backend server catches that click, grabs your hidden/secured secret **API Key**, and packages the user's request into a clean **JSON data file**.

* **Step 3: The Brains (Gemini API)** The JSON file is sent over the internet to the Gemini AI servers. The AI reads the instructions, creates the professional rules text, and sends it back.

* **Step 4: The Delivery (Backend to Frontend)** Our backend server receives the text response from the AI, checks to make sure it looks good, and pushes it directly to the user's screen.

* **Step 5: The Result (User Interface)** The organizer instantly sees their beautifully formatted rules right on the web page, ready to use!
